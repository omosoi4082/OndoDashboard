# 온도 프로젝트 — Claude Code 스타터킷

## 사용법

1. 이 폴더 안의 내용을 Vite 프로젝트 루트(예: 이전에 만든 `pig-farm-cfd-dashboard`를 R3F로
   새로 시작할 프로젝트)에 그대로 복사합니다. `CLAUDE.md`, `docs/`, `.claude/`가 프로젝트
   루트에 있어야 Claude Code가 인식합니다.
2. VS Code에서 해당 프로젝트를 열고 Claude Code를 실행하면, `CLAUDE.md`를 자동으로 읽어
   컨텍스트로 사용합니다.
3. `.claude/agents/` 안의 4개 서브에이전트는 아래처럼 상황에 맞게 불러 씁니다
   (Claude Code에게 "spec-writer 에이전트로 요구사항 문서 정리해줘"처럼 자연어로 요청하면 됩니다):

   - **spec-writer** — 기획서/화면설계 문서를 쓰거나 고칠 때
   - **ui-designer** — 디자인 가이드, 컬러 토큰, AI 이미지 프롬프트 정리할 때
   - **r3f-builder** — 실제 컴포넌트/씬 코드를 만들 때 (대부분의 작업이 여기)
   - **qa-reviewer** — 기능 완성 후, 특히 납품 전 최종 점검할 때

## 권장 진행 순서

1. `spec-writer`로 `docs/00-requirements.md`, `docs/01-screens.md` 초안을 다듬는다
   (이미 계약 범위 기준으로 초안이 채워져 있으니, TBD 항목만 채우면 됩니다).
2. `ui-designer`로 `docs/02-design-guide.md`의 컬러 토큰을 Tailwind config에 반영한다.
3. `r3f-builder`로 화면 셸 → 3D 씬 코어 → 시각화 레이어 → 데이터 연동 순으로 구현
   (이전 대화에서 정리한 7단계 로드맵과 동일한 순서).
4. 매 기능 단위 완료 시, 그리고 납품 직전에 `qa-reviewer`로 문서 대비 점검.

## 왜 문서가 3개뿐인가
정식 SI 납품 문서(요구사항정의서, 화면설계서, 디자인가이드, 테스트계획서 등)를 다 만들면
2개월짜리 프로젝트에서 시간이 너무 많이 듭니다. 대신 "개발에 실제로 필요하고, 클라이언트에게
그대로 보여줘도 되는" 최소 문서 3종 + `CLAUDE.md`(AI 작업 컨텍스트)로 압축했습니다.
문서가 코드보다 먼저 갱신되게만 하면, 이 3개로 기획~디자인~구현~납품 전 점검까지 다 커버됩니다.
