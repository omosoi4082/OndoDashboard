연산 서버 v1.3.3 — 가시화용 추가 데이터 안내 (2026-10-27, ㈜온도)

[요청 방법]
  기존 요청(/v1/current, /v1/forecast)에 "viz": true 한 줄만 더 넣으면 됩니다.
    { "request_id": "...", "viz": true, "forecast_from": "...", "inputs": [ ... ] }
  "viz" 를 넣지 않으면 지금(v1.3.2)과 똑같은 응답이 나옵니다.

[추가되는 것 — 프레임마다]
  1) frames[].grid.flow   격자 유속
     - grid.temp, grid.rh 와 같은 점, 같은 순서 (2,584점 = 19 × 17 × 8)
     - 격자: 원점 (0, 0, 0) m, 간격 (0.25, 0.25, 0.4) m → x 0~4.5, y 0~4.0, z 0~2.8 m (천장·배기구 벽 포함)
     - 순서: index = i + nx·(j + ny·k)   (i: x, j: y, k: z, x 가 가장 빠르게)  ← geometry.json 의 indexRule 과 같음
     - 원소 하나 = [u, v, w, |V|]  단위 m/s, 소수 셋째 자리 (기존 frames[].flow 와 같은 형식)
     - 축: x 서→동, y 배기구 벽(y = 0) → 맞은편 벽, z 바닥 → 천장
           w < 0 = 아래로 (천장 급기), v < 0 = y = 0 벽 쪽으로 (배기구로 빠져나감)
     - "-0.0" 은 0 과 같습니다.

  2) frames[].supply   급기 조건
     airflow_m3h     급기 풍량 [m³/h]  (= 환기횟수 × 방 체적 50.4 m³)
     ach             환기횟수 [회/h]
     inlet_velocity  급기구 면 평균 유속 [m/s]  (= 풍량 ÷ 급기구 3곳 면적 0.6595 m²)
     T_supply        급기 온도 [℃]  (쿨링패드 통과 후, 모델 입력값)
     RH_supply       급기 상대습도 [%]
     pad_on          쿨링패드 가동 여부 (true/false)

  기존 frames[].flow (288점) 는 그대로 남아 있습니다.

[화면 구현 참고 — 샘플 HTML 이 한 방식]
  - 입자 출발·소멸은 geometry.json 의 room.inlets / room.outlet 모양을 그대로 쓰면 자연스럽습니다.
    (급기구 사각형 안 천장 바로 아래에서 출발, y = 0 벽의 배기구 원 안에 닿으면 소멸)
    급기구·배기구가 격자 한두 칸 크기라 격자 값만으로 출발·소멸을 정하면 흐름이 뭉개져 보입니다.

  - 입자 위치의 유속·온도·습도는 격자 8점에서 삼선형 보간했습니다.
