# 납품본 준비 (2026-10-29 목 작업 / 발송은 10/30 금 예정)

10/26 추가 요청과 10/28 회신을 반영한 **납품본**이다. 10/22 납품본 이후 두 번째다.

## 왜 답을 기다리지 않고 먼저 만들었나

10/29 테스트 결과(`20261029-테스트결과-확인.md`)의 실패 7건은 전부 예측 모드 "예측 서버 연결 안 됨"이고,
원인은 온도 측 답(10/30)을 봐야 갈린다. 그때 "답을 받기 전까지 납품 파일은 만들지 않는다"로 적었는데,
**사용자 지시로 바꿨다**(2026-10-29): "온도측 오류일 수 있으니깐 우리 오류 없으면 확인되는 대로 빌드 파일
주게 납품 파일 만들어 줘." 즉 **만들어 두고, 보내는 것만 답을 보고 결정한다.**

우리 쪽 오류 여부부터 봤다 — `npm run typecheck` 통과, 단위 테스트 **572건 전부 통과**, 아래 패키지 검증에서
나온 실패는 전부 연산 서버 미접속 한 가지였다. 코드 쪽에서 7건을 설명할 만한 것은 찾지 못했다.

작업 전 `flow-particles` → `main` 머지(fast-forward, `74c432a`). 납품본이 어느 커밋에서 나왔는지 `main`에 남는다.

## 만든 뒤에 잡은 화면 오류 — 패키지를 다시 만들었다 (커밋 c24baad)

사용자 확인(2026-10-29 저녁): **전문가 모드에서 `필수값 수정` → 적용하지 않고 `<`(뒤로 가기)로
결과 화면에 돌아와도 분석 항목·배속·단면 높이·타임라인이 그대로 남아 있었다.** 결과 화면을 다시
여는 것이므로 모드에 처음 들어왔을 때와 같아야 한다. `적용` 경로도 같았다.

`ControlModeView`는 10/29에 같은 지적을 받아 `resetViewSettings()`를 넣었는데(에너지↔환경 전환)
`ExpertModeView`에는 빠져 있었다 — `handleBack()`이 `setDrafts` + `setScreen('result')`만 했다.
두 길(적용 성공, 뒤로 가기)을 `openResult()` 하나로 모아 `stop()` + `resetViewSettings()`를 지나가게 했다.
화면 점검에 **B-4-13b**를 더했고(체크리스트 13-1), 그래서 B부는 **66항목**이 됐다.

**패키지는 이 수정들 뒤에 다시 만들었다**(첨부의 크기는 바뀌지 않았다). 재검증:
`check.bat` 7단계 정상(⚠️ 목업 모드 1건), 화면 점검 **정상 65 / 실패 0 / 건너뜀 1**,
서빙되는 번들이 수정본(`index-BkGC4bJp.js`)인지 확인, 소스본도 `openResult`가 들어 있는지 확인.

> 확인 중에 **점검이 거짓으로 실패한 일**이 있었다 — 8080에 예전 서버가 살아 있어 Playwright가
> 그것을 재사용했고(`reuseExistingServer: true`), **수정 전 번들**을 상대로 돌아 "리셋이 안 된다"고
> 나왔다. 화면 점검 전에는 8080에 떠 있는 서버가 **지금 보려는 그 빌드인지** 확인해야 한다
> (페이지의 `assets/index-*.js` 이름으로 바로 알 수 있다).

## 배속을 바꾸면 입자가 줄어 보이던 것 (커밋 096aebc)

사용자 확인(2026-10-29 저녁): **10배로 돌리다 일시정지하고 1배로 바꿔 재생하면 입자가 별로 없다.**
"1·3·10배 전부 입자 수는 고정이어야 하는 것 아니냐"는 지적이 맞다.

입자 수는 고정값이 아니라 **급기구 투입 ↔ 배기구 배출의 평형**이었다. 배기구가 유량 균형보다 많이
빨아들여(10/28~29에 넣은 배기구 흡입·벽면 쏠림이 근처 입자를 끌어당긴다) 평형이 상한의 **60%**에
머문다. 평형값 자체는 배속과 무관하지만 **거기까지 가는 시간**이 배속에 반비례해서, 1배에서는 몇 분에
걸쳐 천천히 빠져 눈에 안 띄고 10배에서는 40초 만에 드러났다.

고침: 급기 밀도에 **여유분 2배**(`FLOW_PARTICLE_EMIT_HEADROOM`). 남는 몫은 빈 자리가 없으면 그냥
버려지므로 **실제 투입 수는 급기 풍량을 그대로 따라간다**(온도 측 안내 "출발 개수는 airflow_m3h에 비례" 유지).

실측(`config/geometry.json` + 목업 응답, 1/60초 틱, 4,000개):

| 급기 밀도 | 1배 | 3배 | 10배 | 10배 뒤 1배로 |
|---|---|---|---|---|
| 지금까지(x1) | 3,401 (240초 2,858) | 2,691 | 2,356 | 2,431 → 2,445 (안 참) |
| **고친 뒤(x2)** | **3,994** | **3,996** | **3,991** | **3,997 → 3,998** |

풍량 1,049·1,237 m³/h 두 경우 모두 같았다. 회귀 테스트를 붙였다(실제 형상·실제 유속으로 10배 40초를
돌려 95% 이상 남는지 — `flowParticles.test.ts`).
