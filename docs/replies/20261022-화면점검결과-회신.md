### 왜 실패했나 — 점검 방식

- `tests/ui/helpers.ts`의 `expectCanvasNotBlank`는 캔버스를 PNG로 찍고 **파일 크기가 5,000 bytes를
  넘으면** "그려졌다"로 본다. PNG는 같은 색이 반복될수록 작게 압축되므로, 빈 화면(한 색)은 아주 작아진다.
- 2D 단면 히트맵은 정상인데 한 색이라 2,778 bytes로 압축돼 빈 화면으로 잘못 판정됐다.
  "그려졌는가"가 아니라 "색이 여러 개인가"를 보고 있었던 셈이다.
- B-2-10이 찍는 것은 `detail2dCanvas`(히트맵 canvas) 하나뿐이다. 2D 단면 화면은 따로 그려지는 부분이 섞여 있다
  (`Detail2DSection.tsx`).

| 부분 | 그리는 방식 | 지금 점검이 보나? |
|---|---|---|
| 히트맵 | canvas | ✅ 이것만 찍음 |
| 칸막이 선 | 위에 겹친 SVG | ❌ |
| X·Y축 눈금(m) | HTML 글자 | ❌ |
| 색 범례 막대 | `ColorLegend` | ❌ |

| 히트맵 canvas | 내부 해상도 ≠ 0, 픽셀이 불투명하게 칠해졌는지(99% 이상). 2D 컨텍스트라 `getImageData`로 픽셀을 그대로 읽는다. **색 개수는 적어 두기만 하고 판정에 쓰지 않는다** |
| 칸막이 선 | 겹친 SVG가 보이고 `<line>` 개수 > 0 |
| X·Y축 눈금 | `0m`·`4.5m` 꼴 글자가 하나 이상 |
| 색 범례 | 그라데이션 막대(ColorLegend)가 보이는지 |

칸막이는 처음에 `<line>`을 `toBeVisible()`로 봤더니 실패했다. 수평·수직 선은 bounding box가
0이어서 Playwright가 "안 보임"으로 판정한다. 그래서 SVG 자체를 보고 선 개수를 세는 방식으로 바꿨다.
