## B-2-10 분석

캡처(`test-failed-1.png`)를 보면 2D 단면은 **비어 있지 않다** — 축·칸막이 선·범례는 그려졌고,
단면 전체가 **한 색(주황빨강, 약 19.5~20℃)** 이다. 같은 화면 3D 포인트는 노랑·주황이 섞여 있다.
`detail/sectionGrid.ts`는 연산 서버 grid 값에서 `SECTION_Z_M`(0.5 m)에 가장 가까운 z층을 꺼내
2배 보간만 하므로, 원인은 둘 중 하나로 본다.

- (가) 연산 서버가 그 층에 거의 같은 값을 보냄 → 화면 정상, **점검 기준(`expectCanvasNotBlank`)을 조정**.
- (나) 그 층 값이 `range.temp.max`(20℃)를 넘어 전부 최고색으로 칠해짐 → **색 범위 문제, 연산 서버 측 확인**.

판별은 온도 측 PC에서 PowerShell로 단면 최저·최고와 색 범위를 찍어 받는다(아래 메시지 3번).
이 명령은 API 구조(02 문서 5장)를 보고 만든 것이고 **Windows에서 직접 돌려 보지는 않았다**.
그래서 오류가 나면 캡처를 보내 달라고 적었다.

  캡처(15:33) 값은 `단면 온도: 최저 19.69℃ / 최고 20.16℃`, `색 범위: 15.5 ~ 20.5℃`.

### 3번 결과가 무효인 이유 (우리 쪽 명령 버그)

- 오류 `null 배열에 대한 인덱스를 만들 수 없습니다`(NullArray)가 셋째 줄 `$g.size[0]`·`$g.origin[2]`에서 났다.
- `GET /api/detail/geometry`는 ApiOk로 감싸지 않고 Geometry를 그대로 돌려준다
  (`apps/relay/src/routes/detailGeometry.ts`). 그런데 명령은 `.data.grid`를 읽어 `$g`가 null이었다.
- `$n`·`$k`가 null이라 `temp[0..-1]`, 즉 **전체 grid의 첫 칸과 마지막 칸** 두 값만 집계됐다.
  19.69 / 20.16℃는 0.5 m 단면 값이 아니다. 차이도 0.47℃로, 온도 측이 적은 0.1도와 다르다.
- 색 범위는 이번에 15.5~20.5℃였다(10/22 오전 check는 15.5~20℃).
- (가)/(나) 판단은 보류한다.

### 재요청 메시지

제목: **[온도 돈사 대시보드] 2D 단면 확인 명령 재요청 (수정본)**

- `.data`를 빼고 `.grid`로 읽게 고쳤다.
- 층 번호·칸 수도 찍어서 잘못 읽으면 바로 드러나게 했다. 정상이면 `층 1, 323칸`(19×17)이다.
- 이전 창에 남은 변수가 섞이지 않게 PowerShell을 새로 열도록 했다.
- 명령은 `sectionGrid.ts`(`nearestZIndex`·`extractZLayer`)와 같은 층·인덱스를 쓰는지 대조했지만,
  Windows에서 직접 돌려 보지는 않았다.

```
확인 감사합니다. 4번(10분 자동 갱신)은 정상으로 확인됐습니다.

3번은 제가 드린 명령에 오류가 있어 단면 값이 아닌 다른 값이 나왔습니다. 번거로우시겠지만 아래 명령으로 한 번만 더 부탁드립니다. (대시보드를 켜 둔 상태에서, PowerShell 을 새로 열어 붙여 넣어 주세요)

$g=(Invoke-RestMethod http://localhost:8080/api/detail/geometry).grid
$d=(Invoke-RestMethod http://localhost:8080/api/detail/current).data
