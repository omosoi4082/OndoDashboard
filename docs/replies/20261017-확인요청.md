## 1. 기상대 풍속 `CURWIND` 단위 — 재확인 요청 (가장 중요)

지난 2026-10-15에 `CURWIND` 단위를 여쭈었고 **"확인해 보니 m/s가 맞습니다. 지금처럼 m/s로
표시해 주시면 감사하겠습니다"** 라는 답을 주셨습니다. 그대로 두었는데, 이후 실측에서 그 답과
맞지 않는 값이 계속 나와 번거로우시겠지만 한 번 더 확인 부탁드립니다.

**2026-10-17 10:52, 같은 시각 값**

| 출처 | 항목 | 값 |
|---|---|---|
| 기상대 센서(WS1) | `CURWIND` (현재 풍속) | **14.0** |
| 기상대 센서(WS1) | `MAXWIND` (최대 풍속) | **32.0** |
| 기상청 초단기실황 | `WSD` (풍속) | **3.7 m/s** |

같은 시각 기상대 센서의 다른 값은 `RAIN 0`, `SOLAR 897`, 날씨 판정 `맑음`이었습니다.

**m/s로 읽으면 성립하지 않습니다.** 최대 풍속 32 m/s는 보퍼트 12(태풍급) 순간풍속입니다.
볕이 좋고 비가 없는 날의 값으로 보기 어렵습니다.

**km/h로 읽으면 전부 맞아떨어집니다.**

- `CURWIND` 14 km/h = **3.9 m/s** → 같은 시각 기상청 3.7 m/s와 거의 일치
- `MAXWIND` 32 km/h = **8.9 m/s** → 맑은 날의 돌풍으로 자연스러운 값

지난번에는 `CURWIND` 하나(8 vs 3.3)만 근거로 여쭈어 판단하시기 어려웠을 것 같습니다.
이번에는 최대 풍속까지 함께 보여 근거를 보강했습니다.

**현재 처리**: 판단이 설 때까지 화면이 틀린 값을 보여주지 않도록, **km/h → m/s 환산을 적용해
두었습니다**(화면 표기는 기상청과 맞춘 m/s 그대로입니다). 적용 후 같은 시각 두 패널이
**기상대 4.4 m/s / 기상청 4.3 m/s** 로 거의 일치합니다.

**질문**: `CURWIND`·`MAXWIND`의 단위가 **km/h가 맞습니까?**

- **km/h가 맞다면** 지금 적용한 환산을 그대로 두겠습니다. 따로 하실 일은 없습니다.
- **m/s가 맞다면** 환산을 되돌리겠습니다(함수 하나만 바꾸면 됩니다). 다만 그 경우
  맑은 날 최대 풍속 32 m/s가 어떻게 나오는지 한 줄만 알려주시면 좋겠습니다 —
  센서 설치 높이나 계측 방식 때문이라면 그대로 기록해 두겠습니다.

## 2. 전문가 모드 입력 표 — 값을 한 번에 채우는 버튼을 넣어도 될지

주신 전문가 모드 시안대로 입력 표를 **빈 칸으로 시작**하게 만들었습니다(placeholder
"값을 입력해주세요."). 24행 모두 채워야 `적용` 버튼이 활성화되는 것도 시안대로입니다.

그런데 써 보니 **한 번 쓸 때마다 24행 × 3열 = 72칸을 손으로 채워야** 합니다. 실제 사용도
번거롭지만, 특히 **제안 발표나 세미나에서 화면을 시연할 때** 그 자리에서 72칸을 입력하기가
어렵습니다.

**제안**: 표가 **비어 있을 때만** `초기화` 자리에 **`예시값`** 버튼을 두는 방식입니다.

```
표가 비었을 때   :  [ 예시값 ]  [ 적용(비활성) ]     ← 시안에서 이 자리가 비어 있습니다
값이 들어갔을 때 :  [ 초기화 ]  [ 적용(활성) ]       ← 시안과 완전히 동일
```

- 버튼 개수가 늘지 않습니다. 시안에서 `초기화`는 값을 입력해야 나타나므로, 비어 있을 때
  그 자리가 비어 있습니다.
- **값이 채워진 화면은 시안과 똑같습니다.**

**질문 2-1**: 이 버튼을 넣어도 괜찮겠습니까? 원치 않으시면 지금처럼 빈 칸으로 두겠습니다.

**질문 2-2**: 넣는다면 **예시값을 어떤 값으로** 채우는 것이 좋겠습니까?
지금 가진 값은 주신 `mock_expert.json`의 정시 24개인데 **온도 32~37 ℃**인 극한 시나리오라
시연용으로는 부자연스럽습니다. 평상시 자돈방에 가까운 값(예: 온도 22~26 ℃, 습도 55~70 %,
환기량 40~80 %)을 주시면 그대로 넣겠습니다.

## 3. 전문가 모드 입력 표 행 라벨이 `0시 ~ 23시`가 맞는지

새 시안의 입력 표 왼쪽 열이 **`0시`부터 `23시`까지**로 그려져 있어 그대로 구현했습니다.
전에는 "현재 시각 다음 정시"부터 24개(예: 15시에 열면 16시, 17시, …)였습니다.

시안을 주실 때 이 부분에 대한 설명이 따로 없어 확인 부탁드립니다.

**질문 3-1**: `0시 ~ 23시` 고정이 맞습니까? 아니면 전처럼 **현재 시각 다음 정시부터**가
맞습니까?

**질문 3-2**: `0시 ~ 23시`가 맞다면, 이 24시간은 **어느 날**을 뜻합니까?
(오늘 0시부터인지, 아니면 "하루"라는 뜻이고 특정 날짜와는 무관한지)

> 참고로 중계 서버로 보내는 요청 본문에는 시각이 들어가지 않습니다(`rows[24]{temp, rh, vent}`
> 만 보냅니다). 그래서 **화면 라벨 표기의 문제**이고, 연산 서버 쪽에는 영향이 없습니다.
> 결과 타임라인도 지금은 입력 축에 맞춰 `00:00 ~ 24:00`으로 표시하고 있습니다.
