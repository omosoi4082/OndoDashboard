## 테스트 패키지와 다른 점 (`-Delivery`)

`scripts/make-package.ps1`에 `-Delivery` 스위치를 넣었다(커밋 d37374a, docs/08-development.md).

| | 테스트 패키지 | 납품본 |
|---|---|---|
| 문서 | `README.md`(점검 순서) + `테스트-체크리스트.md` | `docs/delivery/README.md` → **사용 안내** 한 장 |
| bat | start / check / setup / **test-ui** | start / check / setup |

- 빌드 포함본에는 `install.bat`이 없으므로 `start.bat`·`check.bat`의 "install.bat 을 먼저
  실행하세요" 안내를 "압축을 다시 풀어 주세요"로 바꿔 넣는다(bat은 cp949로 읽고 쓴다).

## 기상청 서비스키

패키지에 들어간 키는 **사용자 명의로 발급받은 것**이고 활용기간은 **2026-10-09 ~ 2028-10-09**다.
`-KmaKeyExpiry 2028-10-09`로 넣어 사용 안내 3곳(README 2, CLAUDE-구동안내 1)에 마감일이 박힌다.
문서에는 마감일과 함께 **온도 측 명의 재발급 절차**를 적었다 — 공공데이터포털에서
`기상청_단기예보 조회서비스` 활용신청 → **일반 인증키(Decoding)** 복사 → `setup.bat` `[1/3]` 입력 →
서버 재시작 → `check.bat` `[4/7]` 확인. Encoding 키를 넣으면 안 된다는 점도 적었다
(`kmaClient.ts`가 URLSearchParams로 인코딩하므로 Decoding 값이어야 한다).

`-KmaKeyExpiry`는 `-Delivery`에서 **필수**이고, 문서의 `{{KMA_EXPIRY}}` 치환이 하나도 안 되거나
자리표시자가 남으면 스크립트가 멈춘다 — 마감일이 빈 문서가 나가는 사고를 막는다.

## 발송 직전에 잡은 bat 버그 3건 (커밋 dd7b917)

사용자가 납품본 `start.bat`을 두 번 클릭했더니 **창이 번쩍하고 닫혔다**. 원인을 보니
bat 파일을 `npm` 명령으로만 확인해 왔고 **두 번 클릭 경로(cmd /c)로는 돌려 본 적이 없었다.**
세 건 모두 2026-10-18 이후 **모든 패키지에 들어가 있었다.**

| 파일 | 증상 | 원인 |
|---|---|---|
| `start.bat` | 창이 번쩍 닫히고 아무 메시지도 안 남음 | `if not exist ".env" (` 블록 안 `echo [X] 설정 파일(.env)이 없습니다.` 의 `)` 가 블록을 조기에 닫아 `이은(는) 예상되지 않았습니다`로 죽었다. `pause`에 닿기 전이라 창이 사라진다 |
| `check.bat` | 늘 "점검 도구가 없습니다"로 종료 | 경로의 백슬래시가 **CR 바이트**로 바뀌어 있었다 — `"apps<CR>elay\dist\scripts\doctor.js"`. 4099de2에서 들어갔다 |
| `setup.bat` | 늘 "설정 도구가 없습니다"로 종료 | 같은 CR 버그. **그래서 기상청 키 교체가 애초에 불가능했다** — 납품 안내가 setup.bat을 쓰라고 하므로 치명적이었다 |

고친 뒤 **두 번 클릭 방식으로 다시 확인**했다.

| 패키지 | 확인 |
|---|---|
| 납품 ① | `start.bat` → 서버·브라우저 안내까지 정상. `check.bat` → `점검결과.txt` 생성, mock에서 7단계 정상 |
| 납품 ② | `install.bat` → 설치·빌드 성공 → `start.bat` → `check.bat` 7단계 정상, 화면 **57 / 0 / 1** |
| 테스트 ① | `start.bat`·`test-ui.bat` 재확인 |

`setup.bat`은 가드를 지나 대화형 설정 도구까지 들어가는 것을 확인했다(입력은 사람이 해야 한다).
`install.bat`·`test-ui.bat`의 `echo` 안 괄호는 블록 밖이라 문제가 없다(전부 훑어 확인).

**교훈**: bat 파일은 **반드시 `cmd /c`로, 두 번 클릭과 같은 경로로** 돌려서 확인한다.
`npm run doctor`가 되는 것은 `check.bat`이 된다는 뜻이 아니다. 온도 측이 10/22에 `check.bat`
결과를 보내왔던 것도 Claude Code가 `npm run doctor`를 대신 돌린 결과로 보인다.

또 하나 — 23:15에 `check.bat`이 기상청 실황 조회 실패(❌)를 한 번 냈는데, 1분 뒤 같은 API가
정상이었다(`/api/main/weather/kma` → 14.9℃). 상위 서버의 일시적 실패로 본다. 온도 측에서
같은 증상이 반복되면 정시 직후 발표 지연과의 관계를 다시 본다.
