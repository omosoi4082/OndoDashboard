# 납품본 발송 (2026-10-22 목)

같은 날 보낸 점검 기준 수정 패키지(`20261022-점검기준수정-패키지발송.md`)와 별개로,
**테스트용이 아닌 납품본**을 만들어 보낸다. 사용자 지시(2026-10-22):

- "일단 지금 보내는 거 납품완료 파일을 줄 거야."
- "테스트 체크 이런 거 없이 온도에서 어떻게 사용하면 되는지만 필요하다."
- "기상청 키는 내가 발급받은 거니까 온도 측에 다시 받게 해야 된다. 일단 활용 마감 기간은
  적어 주고, 이후 온도에서 발급해 넣으라고 해야 된다."
- 구성은 **빌드 포함본 + 소스본 둘 다**, 점검 도구는 `check.bat`만 남기고,
  `CLAUDE-구동안내.md`는 포함(2026-10-22 확인).

## 테스트 패키지와 다른 점 (`-Delivery`)

`scripts/make-package.ps1`에 `-Delivery` 스위치를 넣었다(커밋 d37374a, docs/08-development.md).

| | 테스트 패키지 | 납품본 |
|---|---|---|
| 문서 | `README.md`(점검 순서) + `테스트-체크리스트.md` | `docs/delivery/README.md` → **사용 안내** 한 장 |
| bat | start / check / setup / **test-ui** | start / check / setup |
| 포함 | `tests/`, `playwright.config.ts`, `@playwright/test`(19 MB) | 없음 (`package.json`의 `test:ui`도 제거) |
| 크기(①) | 69.1 MB / 19.7 MB | **51.2 MB / 15.6 MB** |

- 사용 안내는 **"쓰는 법"** 기준으로 다시 썼다 — 처음 한 번만(Node 설치·압축) → 쓰는 법
  (`start.bat` 하나) → 화면 보는 법 → **기상청 서비스키** → `setup.bat` → 안 될 때 →
  이런 동작은 정상입니다 → 지원 환경 → 파일 안내 → Claude Code 구동.
- 빌드 포함본에는 `install.bat`이 없으므로 `start.bat`·`check.bat`의 "install.bat 을 먼저
  실행하세요" 안내를 "압축을 다시 풀어 주세요"로 바꿔 넣는다(bat은 cp949로 읽고 쓴다).

## 기상청 서비스키

패키지에 들어간 키는 **사용자 명의로 발급받은 것**이고 활용기간은 **2026-10-09 ~ 2028-10-09**다.
`-KmaKeyExpiry 2028-10-09`로 넣어 사용 안내 3곳(README 2, CLAUDE-구동안내 1)에 마감일이 박힌다.
문서에는 마감일과 함께 **온도 측 명의 재발급 절차**를 적었다 — 공공데이터포털에서
`기상청_단기예보 조회서비스` 활용신청 → **일반 인증키(Decoding)** 복사 → `setup.bat` `[1/3]` 입력 →
서버 재시작 → `check.bat` `[4/7]` 확인. Encoding 키를 넣으면 안 된다는 점도 적었다
(`kmaClient.ts`가 URLSearchParams로 인코딩하므로 Decoding 값이어야 한다).

`-KmaKeyExpiry`는 `-Delivery`에서 **필수**이고, 문서의 `{{KMA_EXPIRY}}` 치환이 하나도 안 되거나
자리표시자가 남으면 스크립트가 멈춘다 — 마감일이 빈 문서가 나가는 사고를 막는다.

## 보내기 전 검증

두 zip을 각각 **새 폴더에 풀어서** 돌렸다.

| 확인 | 결과 |
|---|---|
| 내용물 | 테스트 흔적 0건(`test-ui.bat`·`playwright.config.ts`·`테스트-체크리스트.md`·`@playwright/test` 없음), 한글 파일명 정상 |
| ① 받은 그대로(`http` + 192.168.10.91, 개발 PC에서는 미접속) | `start.bat` 서버 정상(HTTP 200). `check.bat` 실패 3건이 전부 "예측 서버 연결 안 됨" |
| ① `mock` 전환 | `check.bat` 7단계 정상. 저장소 점검 도구로 화면 확인 **57 / 0 / 1** |
| ② `install.bat`(= npm install + build) | 설치·빌드 성공 |
| ② 실행 | `check.bat` 7단계 정상, 화면 확인 **57 / 0 / 1** |

**검증에서 버그 하나를 잡았다**(커밋 6fda91b). 납품본에서 `package.json`의 `test:ui`를 지울 때
`Set-Content -Encoding UTF8`을 썼더니 BOM이 붙었고, vite가 PostCSS 설정을 찾으며 루트
`package.json`을 JSON.parse하다 깨져 **소스본의 빌드가 실패**했다
(`Failed to load PostCSS config ... Unexpected token '\ufeff'`). BOM 없이 쓰도록 고쳤다.
폴더 상태로만 확인했으면 못 찾았을 건이다(2026-10-21 규칙이 또 한 번 값을 했다).

## 메일 본문

> 안녕하세요. 납품 파일 보내드립니다.
>
> **1. 보내드리는 것**
>
> - **`ondo-dashboard-납품-20261022.zip`** (15.6 MB) — 빌드까지 끝낸 실행본입니다.
>   **이것만 쓰시면 됩니다.**
> - **`ondo-dashboard-납품-20261022-src.zip`** (8.7 MB) — 소스입니다. 보관용이며,
>   직접 빌드하실 때는 안에 있는 `install.bat` 을 먼저 실행하시면 됩니다.
>
> **2. 쓰는 법 — `start.bat` 하나입니다**
>
> 1. Node.js LTS를 설치해 주세요. 없으면 <https://nodejs.org> 에서 **LTS** 버튼으로 받아
>    "다음"만 누르면 됩니다(설치 후 PC 한 번 재시작).
> 2. 압축을 **한글·공백이 없는 경로**에 풀어 주세요. 예: `C:\ondo\`
> 3. **`start.bat`** 을 두 번 클릭하면 서버가 뜨고 브라우저가 열립니다.
>    안 열리면 주소창에 `http://localhost:8080` 을 넣으시면 됩니다.
>    **검은 창은 닫지 마세요** — 그 창이 서버입니다. 끝내실 때 닫으면 됩니다.
>
> 화면 값은 10분마다 자동으로 갱신됩니다. 연산 서버 주소(`http://192.168.10.91:9000`)는
> 미리 넣어 두었으니 따로 설정하실 것은 없습니다.
>
> 나머지 안내(화면 보는 법, 설정 바꾸기, 안 될 때)는 압축 안의 **`README.md`** 에 정리해
> 두었습니다. Claude Code로 구동하실 경우에는 **`CLAUDE-구동안내.md`** 를 읽으라고
> 지정해 주시면 됩니다.
>
> **3. 기상청 서비스키 — 2028-10-09 까지입니다**
>
> 지금 들어 있는 기상청 서비스키는 **저희 쪽 명의로 발급받은 것**이고, 활용기간이
> **2026-10-09 ~ 2028-10-09** 입니다. 당장 하실 일은 없고 그때까지는 그대로 쓰시면 됩니다.
>
> 다만 **온도 측 명의로 키를 발급해 바꿔 두시는 편이 안전합니다.** 저희 계정 사정과 무관하게
> 쓰실 수 있습니다. 5분이면 되고, 절차는 `README.md` 의 "기상청 서비스키" 항목에 적어
> 두었습니다. 요약하면 이렇습니다.
>
> 1. 공공데이터포털(<https://www.data.go.kr>)에서 `기상청_단기예보 조회서비스` 활용신청
> 2. 마이페이지 → 오픈API → 개발계정에서 **일반 인증키(Decoding)** 복사
> 3. 폴더의 **`setup.bat`** 실행 → `[1/3] 기상청 서비스키` 에 붙여넣기
> 4. `start.bat` 을 닫고 다시 실행
>
> 키가 만료되면 화면 왼쪽 위 기상청 값만 `-` 로 비고, 센서·연산 서버 쪽은 그대로 동작합니다.
>
> **4. 문제가 있을 때**
>
> 폴더의 **`check.bat`** 을 두 번 클릭하시면 센서 서버·기상청·연산 서버 연결을 하나씩 확인해
> 원인과 조치 방법까지 알려 줍니다(결과는 `점검결과.txt` 로 저장됩니다). 해결이 안 되면
