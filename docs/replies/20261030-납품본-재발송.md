## 원인 (상세는 `20261030-온도-회신.md`)

온도 측 3번 답 "연산 서버는 한 번에 1건만 계산하고, 계산 중에 들어온 요청은 바로 503 BUSY"가 결정적이었다.

- 대시보드는 화면을 열면 **현재 모드 연산 1건**을 자동으로 요청한다(`App.tsx:34` `useCurrentDetailPolling`,
  `usePolling`은 접속 즉시 1회 + 10분 주기).
- 그 계산(viz 켜짐 12~25초)이 끝나기 전에 예측 탭을 누르면 **예측 연산이 겹쳐 들어간다**.
  B-3 화면 점검은 `beforeEach`마다 `page.goto('/')` 후 1~2초 안에 예측 탭을 누르므로 겹침이 거의 매번 생긴다.
- 겹침은 경합이라 같은 시간대에 성공·실패가 섞이고, 빨랐던 10/30에는 재현되지 않았다.
- 연산 서버·네트워크 문제가 아니었다.

- **연결 실패(`UPSTREAM_UNREACHABLE`) 재시도는 넣지 않았다**(10/29 문서의 (다)안). 원인이 우리 쪽 겹침이라
  겹침 자체를 없앴고, 연산 서버가 정말 꺼져 있을 때 "연결 안 됨" 표시가 두 배 늦어지는 쪽이 손해다.
- 값·계산 결과는 바뀌지 않는다. 바뀐 것은 요청을 보내는 순서뿐이다.
- 10배속 타임라인(B-3-12)은 **낮에 보낸 판에 이미 들어가 있다**(`ada7401`).

### 기다리는 동안의 표시 (2026-10-30 사용자)

> "예측 결과를 계산하는 중입니다... 글과 로딩처럼 보이는 뭔가가 있어야 될 것 같은데,
> 글만 보이면 화면이 멈춘 것 같잖아" / "Puzzling… 효과처럼 해도 될 것 같아"

줄 세우기를 넣으면서 **기다리는 시간이 길어졌다** — 현재 모드 계산 뒤에 예측이 줄을 서면
최대 50초, BUSY 재시도까지 걸리면 더 간다. 그 동안 글자만 있으면 멎은 화면과 구분이 안 된다.

- `DetailAreaMessage.tsx`에 `LoadingSpinner`(도는 고리)를 두고, 상세 영역의 로딩 문구 앞에 붙였다.
- 글자 자체에 빛이 스쳐 가는 효과(`.ondo-loading-text`, `index.css`) — `background-clip: text`라
  글자 모양 그대로 밝은 띠가 지난다. 움직임 줄이기 설정(`prefers-reduced-motion`)이면 평소 글자색.
- 오류 문구에는 붙이지 않는다(기다려도 끝나지 않는 상태다).
- 메인 화면은 이미 움직이는 막대(`LoadingOverlay`)가 있어 그대로 뒀다.
- **글자 색을 transparent로 두는 방식이라 실제로 보이는지 화면을 찍어 확인했다**(`E:\ondo-verify-20261030-5\loading.png`):
  문구 179×20 px, `background-clip: text`, 애니메이션 `ondo-loading-sweep` 적용, 도는 고리 보임.

네 모드 모두 같은 문구를 쓰므로 현재·예측·전문가·제어에 다 적용된다.

### 화면 점검 도구 버그 — 거짓 실패 (`tests/ui/helpers.ts`)

첫 전체 실행에서 제어 모드 4건(B-5-5~5-8)이 "상세 패널에 오류 문구가 떴습니다: 연결 끊김"으로
실패했는데, **점검 도구 쪽 문제였다.** `detailErrorText`가 `.text-red-300`을 **페이지 전체**에서
찾아 **외기 패널의 "연결 끊김" 배지**(`OutdoorPanel.tsx`)까지 잡았다. 66회 연속 접속으로 기상청
조회가 한 번 실패해 배지가 떠 있었을 뿐, 제어 모드는 정상이었다(같은 항목만 다시 돌리면 8건 전부 통과).
선택자를 상세 패널(`aside`) 안으로 좁혔다. 납품 패키지에는 점검 도구가 없어 **패키지 내용과는 무관**하지만,
고치지 않으면 우리 검증이 계속 거짓 실패한다.

우리 쪽 점검: `npm run typecheck` 통과, 단위 테스트 **589건 전부 통과**(큐 5건 + 재시도 3건 신규).
