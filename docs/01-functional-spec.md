# 01. 기능 명세

원본: Google Docs "기능_명세서_v001_외부용" v-006 (2026.10.05). 온도 대시보드 연동명세서 v1.0은 회의 이전 참고 자료(회의 결정 우선). 화면설계: `design/screen-design.png` (on-01 기본 화면 ~ on-05 제어 모드). 괄호 안 숫자는 화면설계 번호다.

## 1. 전체 구성

- 페이지 이동 없는 단일 대시보드 화면. 네비게이션 바 없음. 1920×1080 기준.
- 좌측: 외부환경(3), 3D 돈사 메인 모델링(4), 정보 판넬(5), 축척(8).
- 우측: 상세보기 패널(6). 항상 노출하며 실험군(EX) 자돈방 데이터만 표시한다. 육성·비육 데이터는 상세에 나오지 않는다.
  - 상단 모드 탭(7): 현재 모드(기본) / 예측 모드 / 전문가 모드 / 제어 모드
  - 모드별 컨트롤 줄(입력 필드, 최적화 버튼, 유동/습도/온도 버튼, 포인트 on/off, 타임라인)
  - 3D 자돈방 뷰
  - 2D 수평단면 뷰 + 우측 색상 범례
- 상단: 로고(1), 날짜·요일·시간(2).
- 배치 세부는 디자이너가 확정한다. 구현은 영역 단위 컴포넌트로 나눠 배치 변경에 대응할 수 있게 한다.

## 2. 메인 화면

| 번호 | 항목 | 동작 |
|---|---|---|
| 1 | 로고 | 이미지(고해상도 이미지는 온도 제공 예정, 그전까지 placeholder) |
| 2 | 날짜·요일·시간 | 현재 시각 표시, 1초 갱신. 예: 2026년 10월 05일 (월) 15:30:24 |
| 3-1 | 기상청 실황 | 날씨 아이콘/풍향/온도/습도. 기상청 단기예보 조회서비스(초단기실황+초단기예보) |
| 3-2 | 미세기후 | 날씨 아이콘/풍향/온도/습도. 농장 기상대 WS1 (TEMP, RH, WIND, RAIN, SOLAR) |

날씨는 `weatherCode`로 받아 아이콘으로 표시한다. 필수 7종(맑음, 구름 조금, 구름 많음, 흐림, 비, 비/눈, 눈) + 선택 2종(맑음·구름 많음의 밤 버전, `isNight`). 값이 없으면 '-'.
| 4 | 메인 모델링 | 자돈방·육성돈방·비육돈방 3개 구역 3D 돈사. 3개 방 모두 호버 시 정보 판넬 표시. 클릭은 자돈방만 가능 |
| 5-1~5-3 | 정보 판넬 | 방 호버 시 온도·습도·환기량·NH3·CO2 표시. 3개 방 모두 표시 |
| 6 | 상세보기 패널 | 항상 노출, 자돈방 데이터만 |
| 8 | 축척(스케일 바) | 막대형, 1 unit = 1 m. 카메라 줌에 따라 막대 길이와 라벨 변경 |

### 3D 모델링 규칙

- 제공된 1층 평면도 기준으로 아래 객체만 모델링한다. 그 외 객체는 만들지 않는다.
  - 박스형 자돈사·육성사·비육사(바닥/벽, 단일 재질)
  - 급기구: 사각 팬, 단일 재질, 3개
  - 배기구: 원형 팬, 단일 재질, 1개
  - 내부 칸막이: Y형, 단일 재질
  - 돼지
- 자돈사는 문이 복도 쪽에 있어 90도 회전 배치하고, 육성사·비육사 위치를 그에 맞춰 이동한다.
- 머티리얼은 바닥·벽·환기팬(메탈, 단일, 급기구·배기구 공통) 3종.
- 돼지: 단일 모델·단일 색상(핑크), 크기 차이는 스케일로만, 애니메이션 없음.
- 실험군(EX) 자돈방만 컬러. 육성·비육은 축사와 돼지 모두 회색 처리한다.
- 회색은 "선택할 수 없는 방"이라는 표시다.
  - 자돈방: 호버 시 정보 판넬 표시, 클릭 가능(커서 pointer).
  - 육성·비육: 호버 시 정보 판넬만 표시(센서 서버 값), 클릭 불가(커서 기본, 클릭 이벤트 없음).
  - 자돈방 클릭 시 동작은 미확정(`05-open-questions.md`). 상세 패널은 클릭과 관계없이 항상 자돈방 데이터를 표시한다.
- 3D 모델 자체 애니메이션은 넣지 않는다.
- 실제 치수와 축사 모델링 자료는 재요청 중이다. 치수는 설정 상수로 분리한다(`docs/05-open-questions.md`).

### 메인 데이터 갱신

- 화면 영역별로 따로 호출한다. 접속 시 1회, 이후 10분마다 각각:
  - 호버 정보: `GET /api/main/rooms`
  - 3-1: `GET /api/main/weather/kma`
  - 3-2: `GET /api/main/weather/station`
- 한 영역이 실패해도 다른 영역은 표시한다. 호버는 rooms 응답값만 사용한다.
- 환기량은 환기팬 FAN1 가동률(%)을 표시한다(확정). FAN2·FAN3는 사용하지 않는다.
- 응답 없는 방·외부환경 항목은 값 대신 끊김 표시.

## 3. 상세 패널 공통 (현재·예측·전문가·제어)

모든 모드의 상세 데이터는 실험군(EX) 자돈방 기준이다. 연산 입력에 쓰는 센서 이력도 자돈방(`/sensors/JE/EX/NH/*`)만 조회한다.

| 번호 | 항목 | 동작 |
|---|---|---|
| 10·15·22·29 | 유동/습도/온도 버튼 | 토글. 하나만 선택. 기본값 온도 |
| 11·16·23·30 | 포인트 on/off | 125개 포인트 표시 여부. 기본값 on |
| 12·18·25·32 | 자돈방 3D | 아래 표현 규칙 |
| 13·19·26·33 | 자돈방 2D 수평단면 | 단면 히트맵 + 우측 그라데이션 범례 |

- 3D 화면의 자돈방에 125개 포인트를 표시한다. 포인트 시작 기준·순서·보간 방식은 온도 제공 자료로 확정한다.
- 포인트 호버 시 X, Y, Z, VALUE 정보 UI 표시. 유동 선택 시 유동 방향 화살표를 함께 표시한다.
- 유동 선택 시 VALUE는 유속 크기 value(m/s).
- 색상 범위는 응답의 `range`(최솟값·최댓값) 기준. 재생형 모드는 전체 프레임 기준 범위를 써서 재생 중 색 기준이 바뀌지 않게 한다.
- 2D 수평단면: 응답의 3D 격자(grid)에서 `SECTION_Z_M`에 가장 가까운 z층(x·y 평면)을 꺼내 2배 보간 후 히트맵으로 그린다. 단면 높이 기본 0.5 m(미확정). 현재 모드에 2D가 필요한지 확인 중이므로 현재 모드의 2D 뷰는 플래그로 숨길 수 있게 한다.
- 버튼 전환은 받은 데이터로만 다시 그린다(재요청 없음).

### 3D 표현 규칙

- 현재 모드: 125개 포인트(구)를 값별 색상으로 표시.
- 예측·전문가·제어 모드: 125개 포인트와 별도로 받는 격자 데이터로 그린다.
  - 온도·습도: grid를 2배 삼선형 보간 → marching cubes 등치면 3~5단계, 반투명, 값 색상.
  - 유동: flowGrid 노드마다 실린더. 방향 [vx, vy, vz], 길이·색상 value.
  - 포인트 on이면 125개 포인트도 함께 표시.

## 4. 모드별 정의

### 4.1 현재 모드 (9~13), 기본 탭

- 상세 화면 진입 시 기본 선택.
- 진입 시 메인 API들과 동시에 `GET /api/detail/current`, 현재 모드 유지 중 10분마다 재호출.
- 입력: 10분 단위 정각 기준 최근 180분 1분 단위 181건(외기 T_out·RH_out, 자돈 fan_pct, 원자료 그대로) / 출력: 125개 포인트·격자, 프레임 1개. 타임라인 없음.
- 온도·습도는 소수점 단위로도 계속 바뀌므로 10분 폴링마다 끝 시각이 바뀐 새 입력으로 연산한다. 같은 10분 구간 안의 재요청만 캐시 응답.

### 4.2 예측 모드 (14~19)

- 탭 선택 시 `GET /api/detail/forecast` 1회.
- 입력(회의 결정): 현재 모드와 같은 형식. 실측 181건 + 기상청 단기예보 1시간 단위 기온·습도를 1분 단위로 같은 값을 채운 1,440건(환기량 null) / 출력: 10분 간격 145프레임(포인트·격자·유동).
- 연동명세서 v1.0의 요약 입력(T_max·T_min·RH_mean + fan T_100·T_50·T_20)과 달라 온도에 확인 중. 요청 빌더는 두 형식 모두 지원하도록 분리.
- 연산 대기 중 3D·2D 영역에 로딩 표시.
- 타임라인(17) 재생.

### 4.3 전문가 모드 (20~26)

- 입력 필드(21): 온도, 습도, 환기량 3개 + 확인 버튼. 입력 필드에서 유효성 검사(숫자 여부, 범위 `EXPERT_INPUT_RANGE`, 빈 값)를 통과한 값만 전송. 실패 시 확인 버튼 비활성화 + 필드 안내 문구. 입력값 범위·단위는 온도 제공 예정.
- 입력 전: 포인트 데이터 없음, 포인트 호버 UI 미노출, 3D 뷰에 "데이터 값을 입력해주세요" 안내.
- 확인 클릭 시 `GET /api/detail/expert?temp=&rh=&vent=`. 현재는 목업 응답.
- 타임라인(24) 재생.

### 4.4 제어 모드 (27~33)

- 에너지 최적화 / 환경 최적화 전환 버튼(28). 기본값 에너지 최적화.
- 탭 선택 시 `target=energy`, 버튼 전환 시 해당 target으로 `GET /api/detail/control`. 현재는 목업 응답.
- 타임라인(31) 재생.

### 4.5 타임라인 (17·24·31)

- 24시간 결과를 10분 단위 프레임으로 재생.
- 재생 / 일시정지 / 정지 버튼. 정지는 첫 프레임으로 되돌린다.
- 재생바는 10분 단위 눈금, 드래그로 프레임 이동 가능.
- 현재 프레임 시각을 표시한다. 재생 속도 기본값은 프레임당 0.5초(설정 상수).
- 재생 중 추가 요청 없음. 3D·2D가 같은 프레임을 표시한다.

## 5. 데이터 기준

- 시간 기준은 외기(기상대 WS1) 온·습도 데이터.
- 현재 모드 입력은 10분 단위 정각 기준 180분, 1분 단위 181건(예: 15:26 요청 시 12:20~15:20).
- 단위 변환은 온도 측에서 고정해 전달한다. 대시보드는 표시 단위만 붙인다.

## 6. 제한 사항

- 로그인·인증, 권한, 세션, 감사 로그 없음.
- DB 없음. 새로고침 시 화면 상태 초기화.
- 다중 사용자 상태 동기화 없음(각 브라우저가 독립 조회).
- 초기 로딩: 3D 모델 최초 로딩 5초 이내, 재방문 3초 이내. 로딩 중 로딩바 표시.
- API 무응답 시 즉시 끊김 표시.
- 별도 배포 없이 로컬 구동. 대시보드와 중계 서버는 한 PC. 온도 측이 PC별로 복사해 이관할 수 있어야 한다.
