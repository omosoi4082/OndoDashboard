## 오늘 끝낸 것

- **relay**:
  - `COMPUTE_VIZ`를 추가했다(기본 꺼짐). `setup.bat` [2/3]에서 on/off를 고르고, `check.bat`과 시작 로그에 상태가 나온다.
  - `grid.flow`(2,584점)와 `supply`를 화면까지 넘긴다.
  - 예측 응답의 `forecast_issued_at: null`이 형식 오류로 막히던 버그를 고쳤다.
- **목업**: 온도 측이 보낸 실제 v1.3.3 응답 4개로 교체했다(`mock/`).
- **유동 입자** (`detail/flowParticles.ts`, `scene/FlowParticles.tsx`). 기준은 **온도 데이터 + 자돈방 안내문**
  (`mock/응답형식_추가안내_v1.3.3.txt`)이다. 샘플 HTML(`Datacenter_v3_1_M2_3D열유동_뷰어.html`)은 **참고만** 한다(사용자 지시).
  - 입자는 빈 방에서 시작해 급기구에서만 출발한다. 개수는 급기 풍량에 비례한다.
  - 배기구 판정은 원(지름 0.4)이 아니라 배기구 격자 한 칸이다(x 2.0~2.5, z 1.2~2.0, 벽에서 0.25 m). **온도 확인 대기 중**이다.
  - 0.02 m/s 미만 상태가 실제 시간 25초 이어지면 그 입자를 급기구로 되돌린다. 벽·바닥 점이 0이라 그 근처에서 멈추기 때문이다.
  - 배속은 1·3·10배 버튼으로 고르고 기본은 10배다. 입자 색은 온도/습도 중에 고른다. 모드 탭을 바꾸면 둘 다 기본값으로 돌아간다.
  - 보간 계산의 메모리 할당을 없앴다. 10배속에서 프레임당 5.7 ms다.
- **제어 모드**: 에너지/환경 최적화를 바꾸면 재생이 처음으로 돌아간다.
- **2D 단면 키우기**: **하지 않기로 했다**(3D를 줄여야 해서 — 사용자).
- **검증**:
  - typecheck와 테스트 548건이 통과했다.
  - 화면 자동 점검 57/0/1은 "멈춘 입자 급기구로" 변경 **전** 기준이다. 그 뒤로는 다시 돌리지 않았다.
  - 사용자가 화면을 확인했다.

## 집에서 할 순서

1. `git pull` → `git switch flow-particles` → `npm install`
2. **`.env` 확인**. `.env`는 저장소에 없으니 집 PC 것을 쓴다.
   - `FARM_AREA_NAME=제주시 아라동`이 비어 있으면 화면 점검 B-1-2가 실패한다.
   - `COMPUTE_MODE=mock`이면 실제 v1.3.3 응답 목업으로 돈다.
3. `npm run typecheck && npm test`
4. `npm run dev` → 예측 모드 → 유동을 한 번 보고, `npm run test:ui`를 돌린다(dev면 `ONDO_UI_BASE_URL=http://localhost:5173`).
5. **온도 회신 보내기**. 초안은 `docs/replies/20261027-v133-반영-회신-메일.txt`이고, 질문은 배기구 판정 범위(원 / 격자 한 칸 / 벽 전체) 하나다.
6. 10/30 납품 준비:
   - `flow-particles`를 main에 합친다.
   - `scripts/make-package.ps1`로 패키지를 만든다.
   - 풀어서 bat 파일들을 두 번 클릭해 확인한다.
