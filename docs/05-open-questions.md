# 05. 미확정 사항

여기 있는 항목은 임의로 확정하지 않는다. "현재 처리"대로 구현하고, 설정값이나 상수로 분리해 나중에 바꾸기 쉽게 둔다. 새로 생긴 미확정 사항은 아래 표에 추가한다.

| # | 항목 | 확인 대상 | 현재 처리 |
|---|---|---|---|
| 1 | 연산 서버 위치(같은 PC / 같은 공유기 내 다른 PC)와 포트 | 온도 | 두 경우 모두 되도록 `COMPUTE_BASE_URL`에서 IP·포트 수정 |
| 2 | 연산 서버가 우리 응답 구조(03 문서 4.2: 값만 담은 frames)를 따를 수 있는지 | 온도 | mock으로 개발 |
| 3 | 125개 포인트 좌표(파일로 한 번) | 온도 | 5×5×5 균등 배치 임시값(`GEOMETRY_FILE`) |
| 4 | 예측 입력 형식: 회의(실측 3시간 + 1시간 예보 1분 확장 24시간, 환기량 null) vs 연동명세서 v1.0(T_max·T_min·RH_mean + fan T_100·T_50·T_20). summary라면 fan 출처 | 온도 | series(회의 결정), `FORECAST_INPUT_FORMAT`로 전환 가능 |
| 5 | series라면 1분 확장 대신 시간별 값(24개) 그대로 받는 것이 나은지 | 온도 | 1분 확장 |
| 6 | 예측 145프레임(마지막 실측 시각부터 0~1,440분) 수용 여부 | 온도 | 145프레임 |
| 7 | 전문가 모드 입력과 `/v1/forecast`의 관계, 전문가·제어 목업 | 온도 | 목업 |
| 8 | 연산 소요 시간(30초 초과 시 작업 등록/조회 방식 제안) | 온도 | 동기 호출, `COMPUTE_TIMEOUT_MS`=60000 |
| 9 | 현재 모드 10분 단위 정각 기준 입력·10분 주기 요청 공유(연산 서버 부하 영향 여부) | 온도 | 10분 단위로 구현 |
| 10 | fan_pct 센서 경로 확정 | 온도 | `JE/EX/NH/FN1/FAN1` |
| 11 | 전문가 모드 입력값 범위와 환기량 단위 | 온도 | `EXPERT_INPUT_RANGE` 넓게 |
| 12 | 농장 위경도(격자 nx·ny, 일출·일몰) | 온도 | `.env` 필수값 |
| 13 | 센서 WIND 값 형식 | 온도 | 숫자면 각도, 문자열이면 그대로 |
| 14 | 미세기후 11~14시 외 비 없을 때 날씨 | 온도 | null('-') |
| 15 | 현재 모드 2D 필요 여부 | 온도 | `SHOW_2D_IN_CURRENT`=true |
| 16 | 2D 단면 높이 | 온도 | `SECTION_Z_M`=0.5 |
| 17 | 온도·습도 메쉬 표현(등치면 단계·투명도) | 온도·디자이너 | 4단계, 0.35 |
| 18 | 자돈방 좌표 원점 확정, 육성·비육 치수 | 온도 | 자돈방은 PINN 모델 v17.0 형상(02 문서 5장) 기준, 나머지 `scene/layout.ts` 임시값 |
| 19 | 로고 고해상도 이미지 | 온도 | placeholder |
| 20 | 타임라인 세부(정지 시 처음, 드래그, 0.5초/프레임) | 개발자 결정 | 상수 분리 |
| 21 | 3-1 라벨 "기상청 실황" | 디자이너 | 문구 상수 |
| 22 | 자돈방 클릭 시 동작 | 온도·디자이너 | 선택 외곽선만 |
| 23 | UI 디자인 가이드 자료 미수신 | 온도 | 수신 전까지 디자인 가이드 문서·에이전트 없음. 수신되면 `docs/06-design-guide.md` 작성 + `ui-designer` 에이전트(`.claude/agents/ui-designer.md`) 추가 |
