# Claude에게 — 이 폴더에서 할 일

이 문서는 **온도 측에서 이 프로그램을 구동할 때** Claude Code가 읽을 안내입니다.
받으신 분이 Claude에게 "이 폴더 구동해 줘"라고 하시면 Claude가 이 문서를 따릅니다.

---

## 역할

**이 폴더에서 할 일은 구동과 상태 확인, 그리고 문제 정리까지입니다.**

### 하지 말 것

- **소스 코드를 고치지 마세요.** 오류가 나도 원인만 찾아 보고하고, 코드 수정은 개발 측이 합니다.
- **의존성 변경, 빌드 설정 변경을 하지 마세요.**
- **`.env`를 직접 편집하지 마세요.** 값을 바꿔야 하면 사용자에게 `setup.bat`을 안내하세요(아래).
- **git 커밋·푸시를 하지 마세요.**

고쳐야 할 것이 보이면 **고치지 말고 사용자에게 알려 주세요.**

---

## 구동 순서

평소 사용은 **`start.bat` 하나로 끝납니다**(서버 실행 + 브라우저 열기). Claude가 대신 할 때는
출력을 읽기 좋게 아래 명령을 쓰면 됩니다.

```bash
# 0. Node.js 확인 (없으면 사용자에게 https://nodejs.org 의 LTS 설치를 안내)
node -v

# 1. 서버 실행 — 이 프로세스는 계속 떠 있어야 합니다(백그라운드로 두세요)
npm start

# 2. 상태 확인 (서버가 뜬 뒤 별도로. 필요할 때만)
npm run doctor
```

서버가 뜨면 로그에 접속 주소와 현재 설정이 찍힙니다.
사용자에게 **<http://localhost:8080>** 을 브라우저로 열도록 안내해 주세요.

> `npm run doctor`는 `check.bat`과 같습니다. **구동에 필요한 단계가 아니고**, 값이 비어 보이거나
> 오류가 났을 때 원인을 찾는 진단 도구입니다.

---

## 상태 확인 결과 읽는 법

`npm run doctor`는 7개 항목을 `✅` / `⚠️` / `❌` 로 출력하고, 실패에는 **원인과 조치**가 붙습니다.
종료 코드는 정상 `0`, 실패가 하나라도 있으면 `1`입니다.

조치는 대부분 셋 중 하나입니다.

1. `setup.bat` 으로 설정을 고치고 서버 재시작
2. 네트워크·전원 등 **프로그램 밖의 문제**(센서 서버 장비, 연산 서버 PC, 인터넷)
3. 기상청 서비스키 만료 — 아래 "기상청 서비스키"

---

## 기상청 서비스키

`[4/7] 기상청` 이 ❌ 로 나오고 인터넷이 정상이면 **서비스키 만료**일 수 있습니다.
패키지에 들어간 키는 개발 측 명의로 발급받은 것이고 **활용 마감일이 {{KMA_EXPIRY}}** 입니다.

이때는 **온도 측 명의로 새 키를 발급해 넣어야 합니다.** 절차는 `README.md`의
"기상청 서비스키" 항목에 적혀 있습니다 — 공공데이터포털에서 `기상청_단기예보 조회서비스`
활용신청 → **일반 인증키(Decoding)** 복사 → `setup.bat` 의 `[1/3]` 에 입력 → 서버 재시작입니다.

키를 넣는 일은 **사용자가 `setup.bat`으로 직접 하시게 안내하세요.** `npm run setup`은 입력을
기다리는 대화형 명령이라, Claude가 비대화형으로 실행하면 멈춘 것처럼 보입니다.

## 설정 바꾸기

기상청 서비스키 / 연산 서버 모드·주소 / 센서 서버 모드·주소를 바꿀 수 있습니다.
**`setup.bat`을 사용자가 직접 실행**하도록 안내하는 편이 확실합니다(위와 같은 이유).
엔터만 치면 기존 값이 유지되고, 저장 전 `.env.bak`으로 자동 백업됩니다.
바꾼 뒤에는 서버를 **다시 시작**해야 반영됩니다.

연산 서버 주소를 바꿀 때는 넣기 전에 브라우저로 `<주소>/v1/health` 를 열어 `"status":"ok"` 가
보이는지 확인하세요. 상세 화면에 **"연산 서버가 이 PC의 접속을 허용하지 않습니다"** 가 뜨면,
이 PC의 내부 IP(`ipconfig`의 IPv4 주소)를 연산 서버 허용 목록에 넣어야 합니다.

## 문제를 정리할 때

사용자가 개발 측에 전달할 수 있도록 **아래를 모아서** 정리해 주세요.

1. `npm run doctor` 출력 전체 (`check.bat`을 쓰면 `점검결과.txt`로 저장됩니다)
2. 화면의 어느 부분인지 (예: "오른쪽 전문가 모드 적용 버튼")
3. 화면에 나온 **오류 문구 그대로**
4. 서버 로그(검은 창)에 찍힌 오류
5. 발생 시각

**추측을 사실처럼 적지 마세요.** 원인이 확실하지 않으면 "확인된 것"과 "추정"을 나눠 적어 주세요.

## 알아두면 좋은 것

이것들은 **오류가 아닙니다.** 사용자가 물어보면 그렇게 안내해 주세요.

- **전문가 모드 결과가 입력값과 무관하게 동일** — 연산 서버가 아직 전문가 모드 계산을 제공하지
  않아 예시 응답을 보여주는 단계입니다.
- **제어 모드에서 에너지/환경을 바꿔도 결과가 같음** — 같은 이유입니다.
- **타임라인 중간에 "입력 조건이 검증 범위를 벗어났습니다(참고용)."** — 연산 결과가 그 구간을
  모델 검증 범위 밖으로 표시한 것을 그대로 보여 주는 것입니다.
- **2D 수평단면이 한 가지 색으로 보임** — 그 높이(0.5 m)의 온도가 고르면 그렇게 보입니다.
  축 눈금·칸막이 선·색 막대가 보이면 정상입니다.
- **육성돈방·비육돈방이 회색이고 클릭되지 않음** — 상세 데이터는 자돈방만 제공합니다(설계대로).
- **육성·비육돈방에 돼지 모델이 없음** — 성돈 3D 모델을 받는 대로 넣을 예정입니다.
